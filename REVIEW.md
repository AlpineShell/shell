# Review instructions

Alpine Shell is a Windows-only Electron desktop shell (main + renderer, Win32 via koffi FFI, PowerShell for system integration, plus a license/release pipeline). Review for correctness that would break the running shell, corrupt a release/auto-update, or bypass a security boundary — not style. Paths are relative to `apps/desktop/` unless noted.

## What "Important" (🔴) means here

Reserve 🔴 for these repo-specific failure classes. Each finding needs a `file:line` citation in the changed code.

- **IPC contract drift** — a channel string must be identical across every layer it touches: the module `handlers` key (or `ipcMain.on`/`broadcast`), the `ipcRenderer.invoke/send/on/sendSync` in `preload.js` under the right namespace, and (for invoke/on only) the type in `src/types/shell.d.ts`. The strongest signal is a literal typo between layers (`volume-get` vs `volumeGet`); lead with that. **Hard precondition:** do not raise an IPC-drift finding unless you have opened and quoted the line in each layer the channel actually touches. "I could not find X in preload" is not evidence of drift — X may be an internal `win.webContents.send` target (e.g. `launcher/show`) or a module-to-module helper. The `shell.d.ts` type side is checked by `tsc` in CI; only flag it when a channel is added with no type at all.
- **License / activation bypass** — `packages/license/src/index.ts` exports only `isWellFormedKey`/`normalizeKey`; `ActivationResponse.signature` is typed (`:16`) but verified nowhere. If a PR adds code that reads `ActivationResponse.status`/`plan`/`expiresAt` and acts on it (gates a feature, unlocks UI) while trusting those fields without verifying `.signature`, flag it: an unverified response must not be treated as valid. Do NOT prescribe a specific algorithm, and do NOT flag the mere absence of activation code.
- **Command-execution surface (`electron/modules/runCommand.js`)** — handlers `run/exec`, `run/exec-terminal` (`:213-214`) are renderer-facing. `expandEnv()` (`:14-19`) expands `%VAR%` in the user query and the result flows into `resolve()`/`splitCommand()`/`shellExecute()`. Flag a PR that lets `expandEnv` output bypass `resolveExecutable` validation, or that routes a user-derived query into a shell **string** (an `exec`/`spawn` command line, a PowerShell `Start-Process`) instead of `shellExecute(file, args)` from `electron/shellExecute.js`, which passes file and arguments as separate `ShellExecuteExW` struct fields and so has no command line to escape.
- **PowerShell / netsh injection** — user-derived values (Wi-Fi SSID/password) interpolated into an `exec`/`spawn`/PowerShell string without escaping. `modules/network.js` interpolates `ssid` into `netsh wlan connect name="${ssid}"` and `ssid`/`password` into profile XML without entity-encoding. Any new interpolation of user input, or a change here that drops escaping, is Important.
- **FFI / Win32 handle safety (koffi)** — a physical-monitor handle from `GetPhysicalMonitorsFromHMONITOR` not freed via `DestroyPhysicalMonitors` in a `finally`; a NEW `koffi.register()` whose returned pointer the diff assigns to a function-local (not module-level) variable (GC → use-after-free while a hook is armed) or that is not `koffi.unregister`'d after `Unhook*`; a new `koffi.load('<dll>')` for a non-core DLL (dxva2, dwmapi, comctl32) not wrapped in try/catch with a null guard at each call site.
- **Window & process lifecycle** — across display hotplug, the cursor-tracker `setInterval` and the `ipcMain.on('topbar/set-active-region', …)` listener must both be torn down in the topbar's `'closed'` handler; `screen.on('display-*')` listeners registered in `startShellMode` must not accumulate if it is re-entered (e.g. setup test-out). Broken AppBar `SPI_SETWORKAREA` pairing (register without matching unregister, or `repositionShell` leaving the shell positioned but the work area reverted) that could leave the desktop unusable.
- **Startup/polling robustness** — a `start(broadcast)` that throws on missing hardware (no external monitor/dxva2, no battery, no Bluetooth radio) and takes module or app startup down with it; a handler that throws instead of catching and returning a sensible fallback (the established pattern).
- **Release / auto-update integrity** — changes to `scripts/publish.js` (`uploadExtensions` must keep `.exe`/`.exe.blockmap`/`.yml`; `installerKeyPattern`; `versionsToKeep>=1`; `compareVersionsDescending` numeric-only — `parseInt` on a non-numeric segment yields `NaN`→0, and pruning keeps only the most-recent `versionsToKeep`, so a mis-sort can drop a needed installer and orphan `latest.yml`), the `build.publish.url` in `package.json`, R2 secret wiring or the semver-tag gate in `.github/workflows/release.yml`, `electron/modules/updater.js` (`autoDownload`/`autoInstallOnAppQuit` must stay `false` (`:101-102`); `CHECK_INTERVAL_MS` (`:9`) not below 1h), the uninstall registry key in `electron/modules/installer.js`, or the `customUnInstall` macro in `build/installer.nsh` that **must** revert the Winlogon `Shell` value to `explorer.exe` before file deletion — a regression locks the user out at next login.
- **Registry parity for a new setting** — every user-adjustable setting is declared once, as an entry in `SETTINGS_REGISTRY` (`src/settings/registry.ts:400`). The settings pages render their rows from it (`src/components/settings/registryPage.tsx`) and the launcher scores the same array directly (`src/components/topbar/launcherPanel.tsx:40`, `:561`), so an entry earns its settings row, its launcher control and settings-window search at once — and a control hand-written into a page earns none of the three. A PR that adds a **new user-adjustable control** — a toggle, slider, select/segmented, colour or hotkey field rendered in `src/components/settings/*Page.tsx` (usually backed by a new `xxx/…-set` pref handler) — must declare it as a `SETTINGS_REGISTRY` entry with its `page`/`group`/`order`, its `applies`, and its `read`/`write` pair on the same `window.*` setter. Rendering it bespoke is allowed where no generic control expresses it, but then the entry must still exist **and** the route must claim its id in `SETTINGS_ROUTE_COVERAGE.renderedByThePage` (`src/components/settings/settingsRoutes.tsx:47`) — `topbar-color` on `appearance` and `brightness` on `displays` are that pattern. The finding is a raw JSX settings row with neither a registry entry nor a coverage claim. Cite the new control's `file:line` in the changed code, name the setter, and name `src/settings/registry.ts` as the file to extend. **Hard precondition:** do not raise this unless you have opened `src/settings/registry.ts` and confirmed no `SETTINGS_REGISTRY` entry already wraps that setter, and checked `settingsRoutes.tsx` for a `renderedByThePage` claim on it. Do NOT flag a surface that is not a single settable value: reorder/hidden-set editors (`trayIconsPage`, the wallpaper "mine" manager in `wallpaperPage`), OAuth connect-disconnect (`calendarPage`), the multi-field arrangement editor (`displaysPage`), per-row list actions (uninstall in `appsInstalledPage`/`pluginsPage`, force-close in `appsRunningPage`), or a rename/move of an existing option.

If a diff touches none of these classes, default to "No blocking issues." and surface at most convention nits.

## Cap the nits

Report at most 6 Nits per review (test suggestions count against this cap). If there are more, give the count in the summary instead of posting each inline. If everything found is a Nit, open the summary with "No blocking issues."

## Convention checks (Nit level)

Flag newly introduced violations of CLAUDE.md conventions:

- Code comments (this codebase is comment-free except `// eslint-disable*` directives).
- `default` exports anywhere except React components.
- A type added inline in a component/hook instead of `src/types/shell.d.ts` (e.g. an inline `Window` augmentation).
- A read-only hook that reimplements fetch+subscribe instead of using `useShellState`.
- A one-shot shell call that spawns PowerShell directly instead of `runPowerShell` from `electron/powershell.js`.
- File naming not in camelCase, or a hook file not named after its single exported `useXxx`.
- A renderer hook that calls an **unsubscribe-returning** API but discards the returned function instead of calling it in `useEffect` cleanup. Verify against `preload.js` that the specific method returns `() => …` before flagging: `onStartupChanged`, `onCatalogChanged`, `onConfigChanged`, `onOpenAppsChanged`, `onWifiScanUpdated`, `onBluetoothChanged`, launcher `onCloseMenus`/`onStartClose`/`onHide`, and topbar `onCloseMenus` do return one — but topbar `onColorChanged`/`onForegroundColorChanged` and screenshot/alttab `onHide` return void; do not flag discarding their result.

## Test suggestions (Nit; Important only for license/security logic)

When a PR adds or changes **pure, testable logic** in the style this repo unit-tests with `bun test` and co-located tests (`electron/knownApps.test.js`, `electron/modules/startupState.test.js`, `packages/license/src/index.test.ts`), suggest adding/updating a test, naming the function and the co-located `*.test.{js,ts}`. Applies to parsing/formatting helpers, app-matching, state transitions, and `scripts/publish.js` `compareVersionsDescending`. License-key validation / signature verification in `packages/license` is Important (name `index.test.ts`); everything else is Nit and counts against the cap. Never raise a test suggestion for window/display lifecycle, koffi FFI, PowerShell-invoking modules, or IPC wiring. Do not raise it for changes that only touch `isWellFormedKey`/`normalizeKey` formatting.

## Do not flag (intentional patterns)

- IPC shapes that resemble drift but aren't: request-response handlers with no `broadcast` (`launcher/index`), a module registered in `ipc.register` with `handlers` and no `start()` (`runCommand.js`), boot-time `ipcMain.on` sync listeners (`wallpaper-init`, `bluetooth-init`, `network/wifi-init`) paired with `ipcRenderer.sendSync`, fire-and-forget `ipcRenderer.send` channels (`topbar/set-active-region`), `useShellState` not capturing a (nonexistent) unsubscriber, and module helper exports (`setShells`, `showFromHotkey`, `setShellAppsProvider`, `refresh`).
- Intentional graceful degradation: empty `catch` in cleanup/finalizers (`DestroyPhysicalMonitors`/`Unhook*`/`koffi.unregister`), brightness probe returning `[]` when dxva2 is absent, `regAdd` to HKLM failing under non-admin, `persistStore` write failures, and `try/catch` around `require()` of optional modules in `main.js`.
- A file path or argument handed to `shellExecute(file, args)` (`electron/shellExecute.js`) without escaping — the pair crosses into `ShellExecuteExW` as separate struct fields, never as a command line. This does not exempt a new interpolation into an `exec`/`spawn` string elsewhere.
- Bluetooth addresses and radio actions handed to a `.ps1` through `runPowerShellFile` — it spawns `powershell.exe -File` with an argv array, so there is no command line to escape; the addresses come from device enumeration and every Bluetooth script re-validates them as 12 hex digits (`-Action` through `ValidateSet`). `bluetoothEnableAudioServices.ps1` re-launches itself with `Start-Process -Verb RunAs`, passing only its own path and that validated address; that is not a user-derived command line. Do not escalate the network.js SSID reasoning onto Bluetooth by analogy.
- Module-level cache vars, stored `broadcast`/`broadcastRef`, optional chaining on `window.shell?.tray?.*`, and `version` hardcoded `0.1.0` in `package.json` (bumped only by the release workflow).
- Anything CI already enforces: ESLint style, `bun run typecheck` type errors, `bun.lock` / frozen-lockfile, and the settings-registry invariants asserted by `src/settings/registry.test.ts` and `src/components/settings/settingsRoutes.test.tsx` (unique kebab-case entry ids, two or more distinct keywords, a declared page and a collision-free `order`, an `applies` argued in `docs/settings-decision.md`, a rendered route for every page). Flag a missing registry *entry*, never a missing field on one.

## Verification & re-review

For cross-layer IPC findings, name the specific file each side is (or isn't) wired in. After the first review of a PR, post Important findings only and suppress new nits; do not re-raise an Important finding the author has explicitly acknowledged. When over the nit cap, give only the count — do not recap each nit in the summary. Open the summary with a one-line verdict ("No blocking issues." if only nits), Important findings first with `file:line`.
